# Issues

Bug reports and suggestions are welcome. This page describes how to file one so
it can actually be acted on.

## How to create new issues properly

### Rule zero

Always give your issue a meaningful title as this is the first thing anyone will see.

### Bug reports

Before you submit a bug always search the current list of issues to see if it has been reported already.

Your bug report has to include:

- On what OS did you experience the problem (Windows, Linux etc.)
- What version were you playing:
 - Tiles or Curses (text-based)
 - Version string, shown in the bottom right of the main menu
- Description of the problem written in a way that enables anyone to try and recreate it

Your bug report may include:

- Screenshot(s) as some things are best explained visually
- Save file (e.g. link to a file upload)

Bonus points for:

- Checking if the bug exists on the latest build
- Checking if it is OS specific

The OS and version are very important - it is possible the bug you have
encountered has already been fixed. After that reproducibility is the key, so
write your report with all the necessary details.

Bugs inherited from Cataclysm: Dark Days Ahead are still worth reporting here.
Do not report them to CleverRaven unless you have confirmed they happen in an
unmodified copy of Dark Days Ahead.

### Enhancements and addition ideas

Suggestions are welcome as issues. Search first in case the idea is already open,
and if yours is related but sufficiently different, open a new issue and refer to
the older discussion (use GitHub's `#issue_number` reference system).

Remember to take part in the discussion of your suggestions.

### Questions

Read the included documentation and additional text files first, e.g.
[COMPILING.md](doc/COMPILING/COMPILING.md) if you have problems building. If that
does not answer it, open an issue.

## Contributing code

work on the project, get in touch first at <CDDA_HackJob@protonmail.com>. See
